# Theory
We know how we can select the columns from a table (**projection**, possibly coupled with **renaming**), and we know how to **filter** the rows based on some condition. If we combine these two skills, we can extract very specific data. Let's take a look at how we can do that.

## The steps for a specific example
Suppose that we specifically want a list of all countries having consultancy companies. To extract this data, we have to go through the following steps.

- Filter out all the non-consulting companies. (Filtering)
- Extract the countries for these companies. (Projection)
- Make sure all the countries we have are unique. (Removing duplicates)
This gets us the following query.

```sql
SELECT DISTINCT country
FROM companies
WHERE industry='Consulting;
```

This works, but what are the steps we have taken inside our mind to get here?

## The general query writing strategy

Based on the above example, we can come up with a strategy for writing queries.

- Find which **table** we need data from. For the example, we write `FROM companies`.
- Set up the required **filter**. For the example, we add `WHERE industry='Consulting'`.
- Pick the specific **columns** that we need, possibly renaming them to the required output format. For the example, we add `SELECT country` to the start of our query.
- If we specifically want **unique values**, add `DISTINCT`. For the example, we indeed need this.

Note that the steps above are not in the order in which the query is eventually written. The start of the query (the `SELECT` part) is usually only added at the end. Starting with `FROM`, continuing with `WHERE` and ending up with `SELECT` is a very normal way of writing queries.

Sadly SQL does not allow another keyword order. It requires the action `SELECT` to be at the start. The query `FROM companies WHERE industry='Consulting' SELECT DISINCT country` is not valid.

### GROUP 1 — Select Specific Columns After Filtering
Focus: choosing the correct table, filtering with one condition, selecting only the needed columns.

Retrieve the **first name**, **last name**, **email**, and **phone** of employees whose city is **varCity**.

```sql
SELECT first_name, last_name, email, phone 
FROM employees 
WHERE city = 'varCity'
```

Names and salaries of employees earning more than **varNum**
```sql
SELECT first_name, last_name, current_salary 
FROM employees 
WHERE current_salary > varNum
```

 The first and last name of employees whose phone number is missing
```sql
SELECT first_name, last_name 
FROM employees 
WHERE phone IS NULL
```

### GROUP 2 — Projection + Filtering + DISTINCT (unique values)

Focus: extracting a **unique list** of specific fields after filtering.

Retrieve the unique list of **position** values for all **active** career records (records with `end_date IS NULL`).
```sql
SELECT DISTINCT position
FROM emp_data 
WHERE end_date IS NULL
```

### GROUP 3 — Choosing Columns Thoughtfully + Renaming (AS)
Focus: returning only the meaningful output columns, sometimes renamed, while filtering by a single criterion.

From emp_data, list **e_id**, **salary**, and **start_date** for all career records where salary > **varSalary**.
```sql
SELECT e_id, salary, start_date 
FROM emp_data 
WHERE salary > varSalary
```


Prompt: List the **employee ID** and **current position** (rename the column to `active_position`) for all records without an end_date.
```sql
SELECT e_id, position AS active_position 
FROM emp_data 
WHERE end_date IS NULL
```
