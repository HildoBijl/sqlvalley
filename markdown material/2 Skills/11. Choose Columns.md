# Theory
We know how we can retrieve an entire table in **SQL**, but how do we select only a few of the columns? We'll study the commands needed for it and the options that can be added.

## Select columns (projection)
To retrieve all columns from a table, we use `SELECT *` which means "select all". If we only want to select certain columns (apply **projection**) then we have to specify the column names, separated by commas.
```sql
SELECT company_name, country, num_employees
FROM companies;
```

It is strongly recommended to always pick column and table names that have no spaces and are in lower case. If you really want to deviate from this, you need to wrap the names in double quotation marks, like `SELECT "Num Employees" FROM companies;` or similar. For proper column names these quotation marks are allowed but unnecessary.

## Select unique values

Ideally, in a "clean" database, every table row is unique. Having **duplicate rows** (rows in which every property has the same value) is possible, but it is not a good habit. When you select columns, it often does occur that you get duplicate rows. To filter those out, add the keyword `DISTINCT` right after `SELECT`. This instructs the DBMS to squash sets of duplicates into single rows before returning the result.
```sql
SELECT DISTINCT industry
FROM companies;
```
## Rename columns
In databases the columns have names. When retrieving a table, we can adjust the names that the columns have in our output. This **renames** the columns.

```sql
SELECT company_name AS name, country, num_employees AS people
FROM companies;
```

The addendum `AS` is optional here, and it works just as well without. For readability, it is still recommended to add it.

## Deal with multiple tables

So far we have run queries that only request a single table. Later on we will encounter queries involving multiple tables. In that case it may be confusing which column comes from which table, especially if the two tables have columns with the same name. So we specify this coupling, through the format `table_name.column_name`.

```sql
SELECT
companies.company_name AS name, country, companies.num_employees AS people
FROM companies;
```

When the two tables don't have duplicate column names, this table specification is generally not needed, but it is still recommended for clarity. When the two tables do have duplicate column names, this notation is obligatory.

In case your table names are rather long, you can also rename your tables. This creates a shorter query, which may improve readability. Just as with columns, we may remove `AS`, but its usage is recommended for readability.
```sql
SELECT
c.company_name AS name, c.country, c.num_employees AS people
FROM companies AS c;
```
