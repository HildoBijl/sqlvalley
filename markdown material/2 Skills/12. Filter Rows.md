# Theory
When dealing with data in databases, it is very common to look for certain rows in a table: **filtering**. In **SQL** we can do so by appending the query with the keyword `WHERE`, followed by the condition we want to filter on. This condition can be set up in a myriad of ways, so let's browse through the possibilities.

## Set up equality-based conditions

The most common filter is on equality: we want some row property to have a certain value. We usually set up this condition using an **equals sign**, in the format `column_name = some_value`. We can for instance find all companies with exactly 200.000 employees.

Let's study what the DBMS does internally when it receives a query like this. First it pulls the table from memory. (Or at least, the necessary parts of it.) Then, for every row, it evaluates the condition. To do so, it replaces the column name `num_employees` by the respective value _of that row_. Then it checks if the left and right side of the equals sign have the same value. If so, the condition evaluates as `TRUE` and the DBMS keeps it around. If not, the condition evaluates as `FALSE` and the DBMS removes it from the output. After doing this for all rows, the remaining output is sent back.

Note that this mechanism also allows us to compare two different columns with each other. We can set up a condition `column1 = column2`, which gets us all the rows where these two columns have equal value.

We can set up a similar comparison with text. We could for instance find all companies in the 'Entertainment' industry. This comparison is case sensitive.

## Set up larger/smaller than conditions

Instead of requiring equality, we can set up larger/small than conditions. As is customary in mathematics, we use `>` for **larger than** and `<` for **smaller than**. We could for instance find all companies having _more_ than 200.000 employees.

## Set up special comparisons

There are dozens of extra comparison options. One possibility is to add wild cards to text comparisons. This is done through the `LIKE` comparison. Using `LIKE` is like using `=`, but it allows us to use the `%` symbol as a filler to represent "any text". We could for instance find all companies having "the" anywhere in their name.

For most DBMSs the `LIKE` comparison is case insensitive. For some DBMSs it is case sensitive, but there is a case insensitive `ILIKE` equivalent. To invert the result, you can use `NOT LIKE`.

You may remember that table cells can have the special value `NULL` which means "unknown" or "not applicable". You can filter for `NULL` values using the comparison `column_name IS NULL` or similarly `column_name IS NOT NULL`.

The `NULL` value is special in that it represents "some unknown value". That is why the equals comparison `=` _never_ works for `NULL`. That is, `NULL = NULL` always evaluates as `FALSE`. The reason is that "some unknown value" is generally not equal to any other unrelated "unknown value". If you want to check for `NULL` values, always use `IS` instead of `=`.

### GROUP 3 — Filtering NULLs, non-NULLs, and combined conditions
Covers: `IS NULL`, `IS NOT NULL`, NULL-safe comparisons, filtering incomplete records.

```sql

```

Career records with no end_date (still active)
```sql

FROM emp_data

```

Records where perf_score is unknown
```sql

FROM emp_data
```

```sql
SELECT * 
FROM employees

```

Career records missing both salary AND status
```sql
SELECT * 
FROM emp_data 
WHERE salary IS NULL AND status IS NULL;
```
