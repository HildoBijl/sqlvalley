# Theory
We know how to set up a filter in SQL with one condition. In practice, there are usually multiple conditions that interact with each other in various ways. Let's take a look at how we can combine multiple conditions in SQL.

## Combine conditions using `AND`
Suppose that we want to find all Consulting companies from the Netherlands. We now have two conditions: we want the company to be from the Netherlands _and_ we want it to be in Consulting. To combine these two conditions in SQL, we can use the `AND` keyword.

```sql
SELECT *
FROM companies
WHERE country='Netherlands' AND industry='Consulting'
```

The given query makes sense from a language point of view, but let's take a look at what SQL does behind the scenes. SQL sees one large condition, being `country='Netherlands' AND industry='Consulting'`. For every row, it will evaluate whether this full condition resolves to `TRUE` or `FALSE`. When evaluating conditions, SQL first looks at comparisons (the `=` symbols here) and resolves them. Only then does it look at keywords like `AND` to resolve those. The keyword `AND` always needs a `TRUE`/`FALSE` value on either side, and it _only_ resolves to `TRUE` if _both_ sides are `TRUE`. Otherwise it resolves as `FALSE`.

Let's study a tiny example to clarify the above procedure. Suppose the current row we are considering is a company from the Netherlands that is in the Entertainment industry. In this case SQL resolves `country='Netherlands'` to `TRUE` and `industry='Consulting'` to `FALSE`. The full condition hence simplifies to `TRUE AND FALSE`. Then SQL resolves the `AND` keyword. Since it does _not_ have `TRUE` twice, it resolves to `FALSE`. With the full condition eventually resolving to `FALSE`, SQL will filter this row out and not return it as output.

## Combine conditions using `OR`
Very similar to the `AND` keyword is the `OR` keyword. This keyword resolves to `TRUE` when _at least one_ of the two given values is `TRUE`, and it is `FALSE` only when _both_ values are `FALSE`.


```sql
SELECT *
FROM companies
WHERE country='Netherlands' OR country='United States'
```

It is possible (and common) to combine the `AND` and `OR` keywords. When you do so, _always_ use brackets to separate them. After all, it is very unclear what `TRUE OR TRUE AND FALSE` resolves to, while both `(TRUE OR TRUE) AND FALSE` and `TRUE OR (TRUE AND FALSE)` have a clear result.

## Negate conditions using `NOT`

Suppose that we want to find all companies that are _not_ Consulting companies from the Netherlands. To do so, we can use the `NOT` keyword.

```sql
SELECT *
FROM companies
WHERE NOT (country='Netherlands' AND industry='Consulting')
```

The `NOT` keyword expects a `TRUE`/`FALSE` value after it. It then flips this value around: `NOT TRUE` resolves to `FALSE` and vice versa.

A common trick from logic theory is the expansion of brackets with `NOT` in front of it. If we have any two conditions `c1` and `c2`, then we can also rewrite `NOT (c1 AND c2)` as `NOT c1 OR NOT c2`. Similarly, we can also rewrite `NOT (c1 OR c2)` as `NOT c1 AND NOT c2`. In other words: pulling a `NOT` inside brackets will turn `AND` into `OR` and vice versa.

Using logic theory, we could rewrite the above query to a different version that does the exact same thing. A (somewhat inconsistent) example is

```sql
SELECT *
FROM companies
WHERE NOT country='Netherlands' OR industry<>'Consulting'
```

The `NOT` keyword is evaluated _after_ the comparison, but _before_ the `OR` keyword. The above condition is equivalent to `(NOT (country='Netherlands')) OR (industry<>'Consulting')`. The brackets can be added for clarity, but SQL programmers should know the evaluation orders, so usually they are omitted.

## Merge tables using `UNION`, `INTERSECT` and `EXCEPT`

If we have two tables with identical columns, we can **merge** them together. There are various ways to do so. The first is through the `UNION` operator. This operator merges two tables, and it keeps a row if it is in _either_ (or both) of the given tables. So it kind of functions like an `OR`.

Since the `UNION`, `INTERSECT` and `EXCEPT` keywords do very similar things as `AND`, `OR` and `NOT`, their usage is not so common, but there are a few edge cases where they can be really useful.

Contrary to set theory in mathematics, SQL allows duplicate rows. The `UNION`, `INTERSECT` and `EXCEPT` have fixed rules of how to deal with duplicate rows. If table A has five identical rows, and table B has three identical rows, then their `UNION` has five rows (maximum), their `INTERSECT` has three rows (minimum) and their `EXCEPT` has two rows (A minus B).

## Use common SQL short-cuts
There are various short-cuts in SQL that allow you to write basic queries more succinctly. For instance, if we want to find all companies having between 200.000 and 300.000 employees (inclusive), we could use the condition `num_employees >= 200000 AND num_employees <= 300000`, or we could do the exact same thing using `BETWEEN`.

## Tushar Exercises
- Use the `WHERE` clause with multiple conditions connected by `AND`.
- Ensure each condition targets a specific column with a comparison operator like `<, > `or` =`

### 1. A student is looking to find classmates from India who are above 25 to plan a graduation party.
Task: Write an SQL query to retrieve Name and YearOfBirth from Students table where YearOfBirth > 2000 and Nationality is 'India'.
#### Solution:
```sql
SELECT Name, YearOfBirth 
FROM Students 
WHERE YearOfBirth > 2000 AND Nationality = 'India';
```
