# Summary
### Using `AS` to Create Processed Columns
- `AS` can rename columns _and_ create new computed columns.
- Example: `1.2 * price AS price_with_tax`.
- Computed columns can be used in:
    - `WHERE` filters (but only by repeating the expression).
    - `ORDER BY` (column alias _can_ be used).
- Reason: `WHERE` runs _before_ `SELECT`, while `ORDER BY` runs _after_.
---
## Processing Numerical Values
### Arithmetic Operators
- Addition: `x + y`
- Subtraction: `x - y`
- Multiplication: `x * y`
- Division: `x / y`
- Modulo: `x % y` (integer remainder)

### Common Numerical Functions
- Absolute value: `ABS(x)`
- Rounding:
    - `ROUND(x)` → nearest integer
    - `ROUND(x, n)` → n decimals
    - `FLOOR(x)` → round down
    - `CEIL(x)` → round up
- Min/Max:
    - `GREATEST(x, y, ...)`
    - `LEAST(x, y, ...)`
- Other math functions: `POWER`, `SQRT`, `EXP`, `LOG`, `SIN`, `ATAN`, etc.
- Behavior varies by DBMS (e.g., meaning of `LOG(x)`).
---
## Processing Text Values
### Concatenation
- Universal: `text1 || text2`
- Variants (DBMS-specific): `CONCAT()`, `text1 + text2`
### Text Functions
- Length: `LENGTH(text)`
- Trim whitespace: `TRIM(text)`
- Change case: `UPPER(text)`, `LOWER(text)`
- Replace text: `REPLACE(text, old, new)`
- Find substring position: `CHARINDEX(sub, text)` (case-sensitive)
- Substring extraction: `SUBSTRING(text, start, length)` (1-indexed)
---
## Processing Date/Time Values

### Current Time
- `CURRENT_DATE`, `CURRENT_TIME`, `CURRENT_TIMESTAMP`
- Sometimes also `NOW()`
### Date/Time Arithmetic
- SQLite: use `DATE()`, `TIME()`, `DATETIME()` with modifiers like `'-7 days'`
- Other DBMSs use different functions.
### Formatting Dates
- SQLite: `STRFTIME(format, datetime)`  
    Example: `STRFTIME('%Y-%m-%d', CURRENT_DATE)`
### Extracting Date Parts
- Most DBMSs: `EXTRACT(part FROM datetime)`
- SQLite: use `STRFTIME('%m', datetime)` → returns text
    - Convert to number with `CAST(... AS INT)` if needed.
### General Advice
- Date/time handling differs significantly across DBMSs.
- Always check documentation and test carefully.
# Theory
We know how to **rename** columns using the (optional) `AS` command. But this command can be used for far more. We can also **process columns**: manipulate and/or combine various columns to create new ones. We'll first study the general application of this idea, and then dive deep into _how_ to process the values.

## Set up and apply processed columns

Suppose that we have a list of goods with corresponding prices before tax. We could calculate their prices after tax by multiplying them by a factor, for instance `1.2`. (Or whatever the tax rate is.) In SQL it is possible to directly create a new column `price_with_tax` whose value is `1.2 * price`. This is done through the following query.

```sql
SELECT name, price, 1.2*price AS price_with_tax
FROM inventory
```

If you already know how to apply [[12. Filter Rows|filtering]]: you can use these calculated quantities in the filter too. Just add `WHERE 1.2*price < 1000` or similar to your query. And identically, if you already know how to apply [[13. Sort rows|sorting]]: you can sort based on these calculated quantities as well. Just add `ORDER BY 1.2*price DESC` or similar.

> [!info] You usually _cannot_ use newly created column names like `price_with_tax` in your filter, because the `WHERE` command is executed _before_ the `SELECT` command. You _can_ use these new columns in your sorting though, because the `ORDER BY` command is executed _after_ the `SELECT` command.

## Process numerical values

Now that we know how to use processed columns, let's take a look at how exactly we can process them. We start with columns containing numbers.

For numbers, we mostly apply all sorts of arithmetic. The most common operations are the following.

- **Addition**: `5 + 2` becomes `7`.
- **Subtraction**: `5 - 2` becomes `3`.
- **Multiplication**: `5 * 2` becomes `10`.
- **Division**: `5 / 2` becomes `2.5`.
- **Modulo**/**Integer remainder**: `5 % 2` becomes `1`.

Next to general arithmetic, there is a wide variety of functions that can be used.

- **Absolute value**: `ABS(x)` gives the absolute value of `x`.
- **Rounding**: `ROUND(x)` rounds `x` to the nearest integer. `ROUND(x, 2)` rounds `x` to two decimals. `FLOOR(x)` rounds `x` _down_ to the nearest integer lower than `x`. `CEIL(x)` rounds `x` _up_ to the nearest integer higher than `x`.
- **Maximum**/**Minimum**: `GREATEST(x, y, z)` gives the highest value of the three numbers `x`, `y` and `z`. `LEAST(x, y, z)` gives the lowest value of the three numbers `x`, `y` and `z`.
- **Mathematical functions**: `POWER(x, y)` calculates `x^y`. `SQRT(x)` calculates the square root of `x`. `EXP(x)` calculates `e^x`. And there is a wide variety of other functions, like, `LOG(x)`, `SIN(x)`, `ATAN(x)`, and so forth.

Every DBMS has its own variations of these functions. For instance, `LOG(x)` is a base-10 logarithm in MySQL and a natural logarithm in PostgreSQL. Always check out the specifications for your DBMS.

## Process text values

The most common thing to do with text is concatenate multiple pieces of text. This is formally done through `||`.

```sql
SELECT first_name, last_name, first_name || ' ' || last_name AS full_name
FROM customers;
```

The notation with `||` works in all large DBMSs. Some DBMSs also allow `CONCAT(first_name, ' ', last_name)` while others allow `first_name + ' ' + last_name`. As usual, things vary per DBMS.

Then there is a large variety of text processing functions.

- **Text length**: `LENGTH('Hello world')` becomes `11`.
- **Trimming**: `TRIM(' user input ')` becomes `'user input'`, removing spaces at the start/end.
- **Upper/lower case**: `UPPER('Hello')` becomes `'HELLO'` and `LOWER('Hello')` becomes `'hello'`. This is useful when checking if two columns `A` and `B` are (case-insensitive) equal to one another: just check if `LOWER(A) = LOWER(B)`.
- **Text replace**: `REPLACE('Hello world', 'world', 'SQL Valley')` becomes `'Hello SQL Valley'`.
- **Text search**: `CHARINDEX('wor', 'Hello world')` becomes `7`. Note that this is case sensitive: `CHARINDEX('wor', 'Hello World')` becomes `0` which indicates "not found".
- **Part of text**: `SUBSTRING('Hello world', 3, 7)` becomes `'llo wor'`. The first number is the _start_ and the second number is the _length_. SQL is 1-indexed: start at `1` to start at the beginning.

## Process date/time values

Working with dates and times is always tricky in SQL, since the various DBMSs have implemented things rather differently. The only thing they agree on is how to get the **current time**. This is done using the keywords `CURRENT_DATE` for `2025-11-23`, `CURRENT_TIME` for `15:01:14`, or `CURRENT_TIMESTAMP` for `2025-11-23 15:01:14`. Although some DBMSs also use the short-hand `NOW()`.

Often we want to do **arithmetics with time**. For instance, we want to see if something happened in the past week, which means we need the time of last week. In SQLite (which is used here on SQL Valley) this is done through the `DATE` function, the `TIME` function, or the `DATETIME` function, depending on which data type you're using. You pass this function the given date/time, and then add one or more modifiers like `'-7days'`. So `DATE(2025-11-23, '-7days')` becomes `2025-11-16`. Other DBMSs have different time manipulation functions.

If we have a time, we can also **display**/**format** it in various ways. In SQLite this is done using the `STRFTIME(format, datetime)` function. For instance `STRFTIME('%Y-%m-%d %H:%M:%S', DATETIME(CURRENT_TIMESTAMP, '-7 days'))` gives `2025-11-16 15:01:14`. The special characters like `%H` denote things like "Two-digit hour".

A final thing that is often done with dates is extract certain parameters, for instance the month or the year. Pretty much _all_ DBMSs use the `EXTRACT` function for this, except for SQLite. To get for instance the month in SQLite, you can use the by now familiar `STRFTIME` function. For instance `STRFTIME('%m', CURRENT_DATE)` gives the text `'11'`. Note that this is stored as _text_. If you want to do arithmetics with this, you first have to tell SQLite that it is indeed a number, which is done through a so-called type cast. Then `CAST(STRFTIME('%m', CURRENT_DATE) AS INT)` becomes the number `11` which we can then for instance calculate with.

You notice: working with dates is tricky. Always check the specifications of your DBMS, and test your queries well!

Retrieve the employee ID, start date, and the ratio of salary to performance score for all employees.
```sql
SELECT e_id, start_date, salary/perf_score AS pay_ratio
FROM emp_data;
```

Retrieve the department ID, budget, number of employees, and the budget per employee for all departments.
```sql
SELECT d_id, budget, nr_employees,
       budget / nr_employees AS budget_per_employee
FROM departments;
```

```sql
SELECT e_id, start_date>end_date AS wrong_info
FROM emp_data
```
